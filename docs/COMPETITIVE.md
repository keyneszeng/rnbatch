# 商业化研究笔记

> 状态：初稿，2026-10-23。区分「已核实」和「待核实」，不把猜测写成结论。

---

## 1. 需求是否真实

**结论：真实，但天花板不高，且集中在特定职业。**

这个问题只在一种情况下成立：**文件名需要承载信息，而信息不在文件名里。**

典型触发场景：

| 场景 | 频次 | 痛点强度 |
|---|---|---|
| 项目交付归档（建筑/装修/咨询/律所） | 每个项目一次 | 高 —— 交付给甲方时文件名就是专业度 |
| 摄影/活动跟拍交付 | 每场一次 | 中高 —— 客户拿到 `IMG_4821.jpg` 会不满 |
| 投标/申报材料整理 | 每标一次 | 高 —— 有命名规范要求，错一个被打回 |
| 证据/卷宗归档（法务） | 每案一次 | 高 —— 检索依赖文件名 |
| 个人照片整理 | 偶尔 | 低 —— 一次性，不愿付费 |

**关键判断**：频次是「按项目」，不是「按天」。所以订阅制（月付）的说服力弱，
**买断 + 团队席位**更贴合真实使用节奏。这一点和摄影工具（Photo Mechanic）的定价逻辑一致。

## 2. 竞品格局

### 已核实

| 产品 | 能力 | 关键限制 | 价格 |
|---|---|---|---|
| **纳寻** namesense.app | 规则可复用；支持 PDF / Office / 图片；**可选 AI 按内容命名**；改名前预览；可撤销 | **要求 macOS 13+**；免费版每批 3 个文件；AI 需自备 API Key，Pro 不含额度 | Pro **US$3.99** 一次性（早鸟价） |
| **A Better Finder Rename 12** | 15 类规则、多步改名、EXIF/ID3/Spotlight 元数据标签、正则、CSV 导入、Droplet、预设 | **读不了正文**，只能读元数据；无 AI | 待核实（历史价位约 US$20–25，需查官网 order 页） |
| **Finder 右键重命名** | 替换 / 加前缀 / 编号 | 无内容感知 | 免费（系统内置） |

### 待核实

- Name Mangler 3（Many Tricks）—— 定位接近 ABFR，价格待查。
- Hazel —— 规则自动化强，但触发条件是文件属性，不读正文。
- Windows 侧：PowerToys PowerRename、Bulk Rename Utility —— 均无内容感知，可作为「跨平台机会」的参照。
- **Apple 是否已在 Finder / Spotlight 里内置「按内容命名」** —— 这是最大的黑天鹅，必须持续盯。

### 格局判断

市场分成两层，中间是空的：

```
上层：改名规则引擎（ABFR / Name Mangler）—— 功能极深，不懂内容
下层：免费/极简改名（Finder、批量改名小工具）—— 便宜，不懂内容
空层：内容感知命名（纳寻在做，但被 macOS 13+ 卡住了存量用户）
```

**「内容感知」这一层目前只有纳寻一个玩家，且它的 AI 是外挂的（用户自备 Key）。**
这是窗口期，但窗口不会长。

## 3. 差异化在哪

不是「改名更快」，是「不用先想关键词」。

ABFR 的用户路径是：**先知道要叫什么 → 再配置规则**。
rnbatch 的路径是：**指着文件夹说"按这个项目名改" → 工具自己去文件里找项目名**。

这个差异在 GUI 里很难做（要读正文、要理解、要判断哪个词是项目名），
但在 **AI 原生工具**里是天然的 —— 判断交给模型，执行交给 CLI。

护城河不在代码（`engine.py` 300 行，谁都能抄），在三点：

1. **格式覆盖的脏活**：docx / pptx / xlsx / pdf / 老 .doc / 扫描件 OCR / 中文 NFD 归一化。
   这些东西一个个踩坑踩出来，抄起来费时间。
2. **安全感的工程化**：预览 / 撤销 / 冲突回滚。用户敢把一百个文件交给你，靠的是这个。
3. **工作流嵌入**：WorkBuddy 技能、Finder 拖放、未来的批量监听文件夹。

## 4. 商业化路径（候选，未验证）

### A. 开源核心 + 付费 Pro（推荐先试）

- 开源：CLI + 引擎 + 基础模板。建立可信度，拿 GitHub star 当获客。
- 付费：GUI（Mac 原生）、团队命名规范（可下发统一模板）、审计日志（谁在什么时候改了什么）、
  扫描件 OCR、批量监听文件夹自动整理。
- 定价锚点：纳寻 Pro US$3.99 已经把「一次性买断」的心理价位压得很低。
  **不要跟它拼价格**，往「团队版 / 合规版」走：¥99–199 / 席位 / 年。

### B. 纯 SaaS / 云端处理

弱。文件是客户的核心资产，上传云端阻力极大，且大文件传输成本高。
**本地优先（local-first）是卖点，不是妥协。**

### C. 被集成（B2B2C）

把引擎做成库，卖给做 DMS / 项目管理 / 归档系统的厂商。
单价高、周期长，适合有渠道后再说。

### D. 不商业化，做开源影响力

如果目标只是「自己用 + 简历/影响力」，MIT 开源 + 写好 README 就够了。
**先确认这一点，再决定要不要投入做 GUI。**

## 5. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **平台方内置**（Apple 在 Finder 加"按内容重命名"） | 致命 | 往「团队规范 + 审计 + 跨平台」走，别只做单机功能 |
| 纳寻降价 / 加 Windows 版 | 高 | 它的 AI 要用户自备 Key，体验有断点；把「开箱即用」做成差异 |
| 用户不敢用命令行 | 高 | GUI / 拖放是第一优先级，不是锦上添花 |
| 关键词判断出错导致批量错名 | 中（有撤销兜底） | 强制 preview + 一键 undo，把"错"的成本降到零 |
| 文件名长度 / 非法字符 / 跨盘限制 | 中 | 已在 `sanitize()` 和两阶段改名里处理 |

## 6. 下一步该验证什么（按优先级）

1. **找 5 个真实用户各给一个真实文件夹**，看他们第一反应是「这个我要」还是「我自己改一下更快」。
   如果后者居多，说明频次不足以支撑付费。
2. **测定价**：把纳寻 US$3.99 摆在旁边，问「如果这个卖 ¥68 你会买吗」。
   价格敏感度决定是走买断还是团队版。
3. **确认 macOS 12 存量到底有多大**。如果纳寻真的因为 13+ 丢掉一批用户，
   这批人就是最精准的冷启动池。
4. **查 ABFR 官网 order 页的真实价格**，补上竞品定价表。
5. 决定 License：MIT（最大化传播）vs AGPL（防白嫖做 SaaS）vs 专有。
   **在写第一行 GUI 代码之前定下来。**

---

## 7. 一句话总结

> 这不是一个"改名工具"的生意，是一个**"文件归档规范"**的生意。
> 改名只是入口，真正的价值是让一个团队的文件名从"谁爱怎么起怎么起"
> 变成"有一套能自动执行的规范"。
>
> 如果只做单机改名，会被系统内置功能吃掉；
> 如果做团队规范，就没人跟你抢。
