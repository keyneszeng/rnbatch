# Roadmap

当前 `v0.2.0`：CLI / 本地 Web 应用 / MCP server 三种形态共用同一引擎，40 个测试。

## 已完成

- [x] 正文抽取：docx / pptx / xlsx / pdf / 老 .doc / 纯文本 / 图片 OCR（macOS Vision）
- [x] 模板占位符 `{kw} {n} {n:03} {orig} {date} {type} {ext}`
- [x] 冲突消解 + 两阶段改名 + 撤销日志
- [x] 候选关键词启发式打分（带判断依据）
- [x] **本地 Web 应用**：原生文件夹选择器、候选关键词点选、预览表、一键撤销
- [x] **MCP server**：零依赖，6 个工具，`initialize` 里内置安全指令
- [x] HTTP JSON API + token 鉴权（只监听 127.0.0.1）

## v0.3 — 把"能用"变成"敢交付"

- [ ] **扫描版 PDF 的 OCR**（当前 PDF 只读文字层，扫描件读不出东西）
- [ ] **打包成独立 .app**：双击启动，不再需要终端。Tauri 或 py2app，
      打包后体积控制在 30MB 内
- [ ] **`--dry-run` 默认化**：`apply` 不带 `--yes` 时先打印计划并要求确认
- [ ] **跨盘 / 网络盘保护**：区分 `EXDEV` 和权限错误，给出可操作的提示
- [ ] **`rnbatch scan`**：不改名，只报告"哪些文件不符合命名规范"
- [ ] 支持 `--lower-ext` 统一扩展名大小写

## v0.4 — 规范可下发（团队场景的付费点）

- [ ] **命名规范文件 `.rnbatch.toml`**：放在项目根目录，记录模板、关键词来源、
      排除规则 → 团队成员 `rnbatch apply .` 自动套用，不用每次敲参数
- [ ] **`rnbatch check`**：CI 里跑，检查归档目录是否合规（交付审计场景）
- [ ] **批量监听文件夹**（`watch`）：新文件进来自动按规范改名
- [ ] **Web 应用加"团队模板"页**：规范下发 + 使用统计

## v0.5 — 平台化

- [ ] Windows 版（路径分隔符、非法字符集、无 osascript 的选择器方案）
- [ ] 更多语言的 OCR（当前只有 zh-Hans + en-US）
- [ ] 与 DMS / 项目管理系统集成的回调

## 明确不做

- ❌ **云端上传文件处理** —— 本地优先是核心卖点，不是妥协
- ❌ **自动决定关键词** —— 判断必须有人或 AI 参与并确认，这是安全底线
- ❌ **图片管理 / 相册功能** —— 那是 Photo Mechanic / Lightroom 的地盘
- ❌ **微信小程序** —— 小程序拿不到本地文件夹，只能"上传 → 云端改名 → 下载 ZIP"，
      既破坏本地优先，又逼用户上传几个 G 的文件。真要做移动端，
      不如做"扫码把命名规范同步到电脑"这种辅助角色
