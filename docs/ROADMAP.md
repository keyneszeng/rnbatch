# Roadmap

当前 `v0.1.0`：CLI 能用，跑在真实文件夹上验证过。

## v0.2 — 把"能跑"变成"敢用"

- [ ] **扫描版 PDF 的 OCR**（当前只对图片做 OCR，PDF 无文字层时读不出东西）
- [ ] **`--dry-run` 默认行为**：`apply` 不带 `--yes` 时先打印计划并要求确认
- [ ] **跨盘 / 网络盘保护**：改名失败时的提示更明确，区分 `EXDEV` 和权限问题
- [ ] **`rnbatch scan`**：不做改名，只报告"这个文件夹里有哪些文件不符合命名规范"
- [ ] 支持 `{ext}` 大小写统一（`--lower-ext`）

## v0.3 — 规范可下发

- [ ] **命名规范文件** `.rnbatch.toml`：放在项目根目录，记录模板、关键词来源、排除规则
      → 团队成员 `rnbatch apply .` 就自动套用，不用每次敲参数
- [ ] **`rnbatch check`**：CI 里跑，检查归档目录是否合规（给需要交付审计的场景）
- [ ] **批量监听文件夹**（可选，`watch` 子命令）：新文件进来自动按规范改名

## v0.4 — GUI

- [ ] macOS 原生 App（SwiftUI），拖放 + 预览表 + 一键撤销
- [ ] **关键词高亮**：把正文摊开，AI 建议 3 个候选关键词，点击即用
- [ ] Windows 版（如果需要跨平台）

## 长期（未验证，取决于商业化方向）

- [ ] 团队版：规范下发 + 改名审计日志 + 权限
- [ ] 与 DMS / 项目管理系统集成的 API
- [ ] 更多语言的关键词识别（当前 OCR 只有 zh-Hans + en-US）

## 明确不做

- ❌ 云端上传文件做处理 —— 本地优先是核心卖点
- ❌ 自动决定关键词 —— 判断必须有人/AI 参与并确认，这是安全底线
- ❌ 图片管理 / 相册功能 —— 那是 Photo Mechanic / Lightroom 的地盘
